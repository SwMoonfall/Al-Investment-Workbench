# 备份、恢复与升级

正式数据库：`%LOCALAPPDATA%\AIInvestmentWorkbench\Workspaces\Default\Data\investment.db`。

备份目录：同一工作空间的 `Backups`。日志在 `Logs`。`--data-root` 指定独立工作空间时，三者都以该目录为根。

## 自动与手动备份

应用启动成功后尝试当天自动备份，保持运行时每 30 分钟检查是否跨日。按本机日期，每天最多生成一份 `daily-yyyy-MM-dd.db`，保留最近 7 份每日备份。备份采用 SQLite 在线备份 API，包含已提交 WAL 内容，输出单文件并进行完整性、外键和版本检查；不是直接复制正在写入的数据库。

设置 → 立即备份生成独立 `manual-*` 文件。`daily-*` 的清理不影响手动、迁移前、恢复前或 Demo 删除前备份；这些需用户按空间情况自行保管。设置显示最近自动备份状态，失败会写日志并提示检查磁盘/权限。打开备份目录可复制到另一磁盘；仅保存在本机不能防范整盘损坏。

自动备份是一日一次的快照，不包含当日之后所有编辑；重要批量操作后建议立即备份。

## 恢复步骤

1. 保存正在编辑的内容，设置 → 从备份恢复，选择 `.db`。
2. 确认提示。应用先验证并复制到本工作空间 `Data/restore.pending.db`，随后关闭。
3. 再次启动。程序在独占工作空间锁下，将待恢复副本迁移到当前版本并检查完整性。
4. 替换之前，自动备份当前数据库为 `before-restore-*`。如果安全备份、检查或迁移失败，则不替换原库。
5. 检查通过后 checkpoint 并原子替换文件，再打开页面；不会让运行中的页面沿用旧连接或旧状态。

恢复不合并数据，而是回到备份时状态。恢复前安全副本可用于找回替换前数据。无法恢复来自未知更高版本、无工作台迁移历史、损坏或外键不完整的数据库。

如果启动时待恢复副本失败，原数据库仍在：关闭程序，将 `Data/restore.pending.db` 移至别处保留，再启动即可继续原库。不要删除 investment.db。程序未修改待选的原备份文件。

## 升级保护

安装新版本后首次启动自动处理 EF migrations。已有库先通过只读检查，复制成工作副本；迁移只在工作副本上执行。迁移成功且验证通过后保留 `before-migration-*`，最后替换正式库。故障注入测试验证了 SQL 迁移失败时原始文件字节不变。未知更高迁移版本直接拒绝，避免旧程序误用新结构。

安装器只处理程序文件，卸载默认保留数据库、日志、备份与加密密钥。数据库升级后一般不能直接降级旧程序；应另存数据，再用旧版对应备份创建隔离工作空间核对。

## 备份范围

SQLite 包含业务记录、研究提取文本、AI 审计和用户设置，但不包含外部文件原件、PDF 附件原件或 Secrets 内密钥。请另外备份文件原件；跨电脑/Windows 用户迁移后重新输入 API Key。数据库备份没有加密，按个人研究资料保管。

Demo 位于正式工作空间的 `DemoWorkspace` 子目录，具有独立数据库、日志、备份和标记。重置/删除必须关闭 Demo 窗口，要求标记与路径验证，并拒绝重解析目录。删除前 Demo 数据库安全副本放入正式工作空间 Backups；正式账户不被删除。
